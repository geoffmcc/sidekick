# Jellyfin pack: catalog and content health

`library_audit` and `content_health` are bounded, read-only catalog inspections. They query Jellyfin items beneath configured libraries and report the server's `TotalRecordCount` separately from the returned sample. A sample is not a complete filesystem inventory.

Use `search_media` or the `jellyfin/catalog-search` workflow for title or text searches across the selected user's visible libraries. Each call discovers views from `/UserViews` at runtime, so custom names need no pack configuration and no library names are assumed. The default media types include Movie, Series, Season, Episode, Audio, MusicAlbum, MusicArtist and MusicVideo. Optional `include_item_types`, `years` and `genre` filters can narrow a search. If genre/year filters produce no matches, the same title/type query retries without those optional filters and reports `filters_relaxed`; if still empty, `refinement_suggestions` offers concrete next search clues. Results identify matching libraries, interleave results across libraries, and report `truncated` plus `next_start`; pass that offset to continue. Use `list_libraries` to inspect the selected user's current names and IDs, and pass an exact visible `library_id` to narrow a search. Searches are read-only.

Use `list_media` when individual movie or TV titles are needed. The default route queries Jellyfin's recursive `/Items` collection. Set `user_scoped=true` (or supply `username`/`user_id`) with a discovered `library_id` to use the selected user's `/Users/{id}/Items` view and reject libraries absent from that user's views. It supports `genre` (or comma-separated `genres`), `include_item_types`, `query`, `tags`, `years`, favorite/rating/date filters, sorting, `limit`, and `start`/`start_index`; a returned `next_start` continues a bounded page.

Use `media_suggestions` or `jellyfin/media-suggestions` for a short user-specific set of unplayed picks. It uses recently played genre evidence to rank unplayed candidates, sorts ties by recently added, and excludes items marked played or with a playback position. It also returns a separate continue-watching list. This is a deterministic convenience ranking, not Jellyfin's recommendation engine.

User-aware filtering uses Jellyfin's user-scoped views and item endpoints. When Sidekick connects with one shared administrator API key, selecting a Jellyfin user is application-level scoping; the API key remains server-privileged and does not provide credential isolation between users. Use separate server profiles/credentials or other trust boundaries when users must be isolated from one another.

Set `all=true` to enumerate every matching item across the selected library or server. Enumeration follows Jellyfin pages until the reported total is reached, an empty/short page is returned, or the safety cap is reached. `max_items` defaults to 10,000 and is bounded at that value; inspect `total_record_count` and `truncated` to determine whether the result is complete. Full-library enumeration is still API inventory evidence, not proof that every filesystem media file is reachable.

The audit reports item types, production years, video codecs, overview/image/provider-id presence, runtime availability, audio languages, subtitle languages and normalized item metadata. Missing metadata is an observation from the returned Jellyfin DTO, not proof that a file is corrupt or unreachable. Filesystem accessibility, permissions, mount state and media integrity require an independent host or storage evidence source.

`media_info` is used for a named item, series or season. Series inspection is capped at 100 seasons and 100 returned episodes per season. Episode counts use Jellyfin's `TotalRecordCount` when present; runtime aggregates describe the episodes returned in the bounded response. The action never refreshes metadata, changes user data or mutates the library.

Large libraries should use `library_id` to narrow the audit or consume aggregate results rather than treating the returned item list as exhaustive. Duplicate candidates and metadata findings are evidence for review, never automatic repair instructions.
