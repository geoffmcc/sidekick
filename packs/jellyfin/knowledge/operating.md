# Jellyfin pack: operating model

The pack owns Jellyfin-side evidence and reasoning. It does not manage the host, filesystem, reverse proxy, GPU device mapping, NAS, or hypervisor. Select a configured profile by name; the endpoint is never a model argument. Where host or hypervisor evidence is needed (storage preflight, backup evidence, release lookup) the pack composes the governed `proxmox`, `status` and `web_fetch` tools through its declared manifest permissions — never raw shell.

Read results are bounded and normalized. Diagnostics distinguish observed facts, deterministic conclusions, unknowns, and the next check. Missing optional Jellyfin facilities are reported as unsupported rather than treated as a server failure; an authentication failure always surfaces as `authentication_failed`, never as "unavailable". Log access retrieves only a bounded tail of a server-listed log file and returns redacted summaries (time range, level counts, deduplicated error signatures) — raw log content is never returned. Readiness verdicts (`backup_readiness`, `upgrade_readiness`) and `metrics_summary` are derived from named evidence sources; when evidence cannot be established the result says `not_verifiable` with the reason, not a fabricated status.

`media_info` is read-only and uses Jellyfin item and show endpoints to report normalized item metadata, runtime, codecs, resolution, audio/subtitle stream details, provider ids, season counts, episode counts, and runtime aggregates. Series inspection is bounded to 100 seasons and 100 returned episodes per season; when Jellyfin provides `TotalRecordCount`, it is used for the episode count. The pack never edits metadata, refreshes a library, starts a task, or deletes media as part of this action.
